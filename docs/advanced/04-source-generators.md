# 4. Source generators & analyzers

## What & why

A **source generator** is a compiler plug-in that reads your code and **writes more C# code** during compilation. It is the compile-time alternative to reflection: the output is ordinary code, so it's fast, debuggable, trimmer-safe and AOT-friendly. An **analyzer** is a plug-in that inspects code and reports warnings or errors (and can offer fixes). Both run inside the Roslyn compiler.

You've already used generators without noticing:

| Feature | Generated by |
| --- | --- |
| `[GeneratedRegex]` | the regex source generator |
| `[LoggerMessage]` | high-performance logging |
| `[JsonSerializable]` | `System.Text.Json` serialization code |
| `[LibraryImport]` | P/Invoke marshalling stubs |
| Minimal API request delegates, `ConfigurationBinder` | ASP.NET Core / Extensions generators |

## Using generated code: `partial`

Generators add to your types, so those types are `partial`:

```csharp
using System.Text.RegularExpressions;

public static partial class Patterns
{
    [GeneratedRegex(@"^\d{4}-\d{2}-\d{2}$")]
    public static partial Regex IsoDate();
}

bool ok = Patterns.IsoDate().IsMatch("2026-10-23");
```

You declare the *shape* (a `partial` method with no body); the generator supplies the body. In an IDE you can open the generated file under **Dependencies, Analyzers**; with the CLI, set `<EmitCompilerGeneratedFiles>true</EmitCompilerGeneratedFiles>` to write them under `obj/`.

## How a generator works

Roslyn parses your code into **syntax trees** and builds a **semantic model** (what each name means). An *incremental generator* describes a pipeline:

1. **Find** interesting syntax cheaply (for example, classes with an attribute).
2. **Transform** each candidate into a small, comparable data record.
3. **Emit** source text from that data.

Because every step caches by value equality, the IDE only reruns work for what changed. That is why generators should extract **plain records**, never hold symbols or syntax nodes across steps.

## Writing one: `[AutoToString]`

Goal: put `[AutoToString]` on a class and get a `ToString()` listing its public properties.

**Project setup**, a separate `netstandard2.0` library (generators load into the compiler, which targets netstandard):

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>netstandard2.0</TargetFramework>
    <LangVersion>latest</LangVersion>
    <Nullable>enable</Nullable>
    <IsRoslynComponent>true</IsRoslynComponent>
    <EnforceExtendedAnalyzerRules>true</EnforceExtendedAnalyzerRules>
  </PropertyGroup>
  <ItemGroup>
    <PackageReference Include="Microsoft.CodeAnalysis.CSharp" Version="4.12.0" PrivateAssets="all" />
    <PackageReference Include="Microsoft.CodeAnalysis.Analyzers" Version="3.11.0" PrivateAssets="all" />
  </ItemGroup>
</Project>
```

**The generator:**

```csharp
using System.Collections.Immutable;
using System.Text;
using Microsoft.CodeAnalysis;
using Microsoft.CodeAnalysis.CSharp.Syntax;
using Microsoft.CodeAnalysis.Text;

[Generator]
public sealed class AutoToStringGenerator : IIncrementalGenerator
{
    private const string AttributeName = "AutoToStringAttribute";

    public void Initialize(IncrementalGeneratorInitializationContext context)
    {
        // 1. Always emit the attribute itself, so users need no extra reference.
        context.RegisterPostInitializationOutput(ctx =>
            ctx.AddSource("AutoToStringAttribute.g.cs", SourceText.From("""
                namespace AutoToString
                {
                    [System.AttributeUsage(System.AttributeTargets.Class)]
                    internal sealed class AutoToStringAttribute : System.Attribute { }
                }
                """, Encoding.UTF8)));

        // 2. Find classes carrying the attribute, and turn each into plain data.
        var models = context.SyntaxProvider.ForAttributeWithMetadataName(
                "AutoToString.AutoToStringAttribute",
                predicate: static (node, _) => node is ClassDeclarationSyntax,
                transform: static (ctx, _) => Model.From(ctx))
            .Where(static m => m is not null)
            .Select(static (m, _) => m!);

        // 3. Emit source for each.
        context.RegisterSourceOutput(models, static (spc, model) =>
            spc.AddSource($"{model.TypeName}.AutoToString.g.cs", SourceText.From(Emit(model), Encoding.UTF8)));
    }

    private static string Emit(Model model)
    {
        var sb = new StringBuilder();
        sb.AppendLine("// <auto-generated/>");
        sb.AppendLine("#nullable enable");
        if (model.Namespace is not null) sb.AppendLine($"namespace {model.Namespace};");
        sb.AppendLine($"partial class {model.TypeName}");
        sb.AppendLine("{");
        sb.AppendLine("    public override string ToString() =>");
        sb.Append($"        $\"{model.TypeName} {{ ");
        sb.Append(string.Join(", ", model.Properties.Select(p => $"{p} = {{{p}}}")));
        sb.AppendLine(" }\";");
        sb.AppendLine("}");
        return sb.ToString();
    }

    // Plain data with value equality: lets the incremental pipeline cache results.
    private sealed record Model(string? Namespace, string TypeName, EquatableArray Properties)
    {
        public static Model? From(GeneratorAttributeSyntaxContext ctx)
        {
            if (ctx.TargetSymbol is not INamedTypeSymbol type) return null;
            var props = type.GetMembers()
                .OfType<IPropertySymbol>()
                .Where(p => p.DeclaredAccessibility == Accessibility.Public && !p.IsStatic)
                .Select(p => p.Name);
            return new Model(
                type.ContainingNamespace.IsGlobalNamespace ? null : type.ContainingNamespace.ToDisplayString(),
                type.Name,
                new EquatableArray(props.ToImmutableArray()));
        }
    }
}

// ImmutableArray<T> compares by reference, so wrap it for structural equality.
internal readonly struct EquatableArray(ImmutableArray<string> items) : IEquatable<EquatableArray>
{
    private readonly ImmutableArray<string> _items = items;
    public IEnumerable<string> Select(Func<string, string> f) => _items.Select(f);
    public bool Equals(EquatableArray other) => _items.SequenceEqual(other._items);
    public override bool Equals(object? obj) => obj is EquatableArray o && Equals(o);
    public override int GetHashCode() => _items.Aggregate(17, (h, s) => h * 31 + s.GetHashCode());
}
```

(The full pipeline rules are subtle. The point is the shape: *filter → transform to equatable data → emit*.)

**Using it** from an app project:

```xml
<ItemGroup>
  <ProjectReference Include="..\AutoToString.Generator\AutoToString.Generator.csproj"
                    OutputItemType="Analyzer" ReferenceOutputAssembly="false" />
</ItemGroup>
```

```csharp
using AutoToString;

[AutoToString]
public partial class Person
{
    public string Name { get; set; } = "";
    public int Age { get; set; }
}

Console.WriteLine(new Person { Name = "Ada", Age = 36 });   // Person { Name = Ada, Age = 36 }
```

## Rules of thumb for generators

- **Be incremental** (`IIncrementalGenerator`). The older `ISourceGenerator` is deprecated and slows the IDE.
- **Be deterministic and side-effect free.** No file or network access, no clocks.
- **Never put symbols or syntax nodes into your pipeline data.** Extract strings and records.
- **Generate only additive code.** Generators can't change or delete existing code.
- **Report problems as diagnostics** (`ReportDiagnostic`) rather than throwing.
- **Test with snapshot tests** (the `Verify.SourceGenerators` package is popular) and the `CSharpGeneratorDriver`.
- Target `netstandard2.0` and keep dependencies tiny.

## Analyzers

An analyzer examines syntax or semantic information and reports **diagnostics**:

```csharp
[DiagnosticAnalyzer(LanguageNames.CSharp)]
public sealed class NoConsoleInLibraryAnalyzer : DiagnosticAnalyzer
{
    static readonly DiagnosticDescriptor Rule = new(
        id: "DEMO001",
        title: "Don't use Console in library code",
        messageFormat: "Use ILogger instead of Console.{0}",
        category: "Design",
        defaultSeverity: DiagnosticSeverity.Warning,
        isEnabledByDefault: true);

    public override ImmutableArray<DiagnosticDescriptor> SupportedDiagnostics => [Rule];

    public override void Initialize(AnalysisContext context)
    {
        context.EnableConcurrentExecution();
        context.ConfigureGeneratedCodeAnalysis(GeneratedCodeAnalysisFlags.None);
        context.RegisterOperationAction(ctx =>
        {
            var call = (IInvocationOperation)ctx.Operation;
            if (call.TargetMethod.ContainingType.ToDisplayString() == "System.Console")
                ctx.ReportDiagnostic(Diagnostic.Create(Rule, call.Syntax.GetLocation(), call.TargetMethod.Name));
        }, OperationKind.Invocation);
    }
}
```

A **code fix provider** can pair with it to offer one-click corrections in the IDE.

You can tune severities without writing code, in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.CA2007.severity = warning
dotnet_diagnostic.IDE0005.severity = suggestion
dotnet_analyzer_diagnostic.category-Performance.severity = warning
```

Valuable existing analyzers: the built-in .NET analyzers (CA rules), Roslynator, StyleCop.Analyzers, Meziantou.Analyzer, and the Microsoft.CodeAnalysis.PublicApiAnalyzers for tracking API changes.

## Generators vs reflection vs T4 templates

| | Reflection | Source generator | T4/text templates |
| --- | --- | --- | --- |
| When it runs | run time | compile time | before compile, manually |
| Speed | slow | as fast as hand-written | as fast as hand-written |
| AOT/trim safe | no | yes | yes |
| IDE support | n/a | live, incremental | separate step |
| Effort | low | high | medium |

If a library only needs to work with a handful of types, reflection or a hand-written method is usually fine. Generators pay off in libraries used everywhere.

## Common mistakes

- **Holding `ISymbol`/`SyntaxNode` in pipeline output,** which defeats caching and leaks memory.
- **A generator that emits non-deterministic text** (timestamps, hash-set order).
- **Forgetting `partial`** on the user's type.
- **Targeting a modern TFM** for the generator project. It must be `netstandard2.0`.
- **Doing heavy work in the `predicate`** (it runs on every syntax node on every keystroke).
- **Name collisions in `AddSource` hint names.**

## Exercises

1. Use `[GeneratedRegex]` to replace a `new Regex(...)` in one of your earlier programs and compare the generated code.
2. Use `[LoggerMessage]` to define a high-performance log method and read its generated source.
3. Build the `AutoToString` generator and add a `[Skip]` attribute on properties.
4. Write a generator that creates an `enum` extension `ToStringFast()` for any enum marked `[EnumExtensions]`.
5. Write the `NoConsoleInLibraryAnalyzer` and make the warning an error for one project through `.editorconfig`.
6. Add snapshot tests that run your generator against sample input.

## Recap

- Generators write ordinary C# at compile time. They replace reflection with fast, AOT-safe code.
- Incremental generators filter syntax, transform it into equatable data, then emit source.
- Analyzers report diagnostics; `.editorconfig` tunes their severity.
- Keep generators deterministic, additive and symbol-free in their pipeline data.
